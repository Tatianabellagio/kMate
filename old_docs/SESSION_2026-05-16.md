# Session 2026-05-16 — v3qc panel decisions (xwu QC match + 7-cactus PG swap)

This session decided the **v3qc panel** rebuild: match xwu's GrENE-Net QC pipeline on the PG side, and swap 7 low-quality cactus assemblies to PG-genotypes from their 1001G short reads.

## TL;DR

1. **Match xwu V4 < 0.01 + GQ ≥ 20 on the PG side.** Drops ~35.8% of PG-side Chr1 records (~394K of 1.1M). Conservative; same threshold as our hapFIRE comparator panel; the only V4 value with prior validation.
2. **Exclude 2 cactus assemblies** (was 7 originally; reduced after empirical concordance check). Net cactus = 78. PG-substitute their ENA short reads → PG = 153. Total panel = 231 preserved.
3. **Empirical concordance trumps a-priori coverage flags.** LOO genotyping of the 75 cactus founders from their 1001G short reads showed Fernando's 7 coverage/het flags do NOT track with actual assembly quality — 4 of 7 flagged founders have disagreement at or below the 75-founder median (4.14%). Only 2 flagged founders (5772, 9947) are in the catastrophic tail with independent supporting evidence (mislabel for 5772; coverage flag aligned with concordance for 9947). See `LOO_DISAGREEMENT_DISTRIBUTION.ipynb`.

## Decision 1 — V4 < 0.01 PG QC threshold (matches xwu)

**Context.** GrENE-Net's xwu pipeline applies an HWE excess-het filter (V4 = AC_Het / AC < 0.01) after biallelic + MAC + Beagle filters. On our 151-founder PG-side Chr1 (1,099,733 biallelic records), 35.8% have V4 ≥ 0.01 — clustered at V4=1.0 (all-het no-hom-alt) and V4=0.5 (1 het + 1 carrier total = singleton-as-het). These are deeply suspicious in inbred A. thaliana.

**Decision.** Apply **V4 < 0.01** exactly (xwu's value), plus **FORMAT/GQ ≥ 20** (matches GATK genotype-quality convention).

**Why this and not looser?** Looser thresholds (V4<0.02 / 0.05) preserve more records but weaken the apples-to-apples reasoning with the hapFIRE comparator panel. xwu's threshold is the only one with prior validation in this pipeline.

**Rejected alternatives.**
- V4 < 0.02 / 0.05 / 0.10: kept for completeness but no validation.
- Beagle imputation: hard-rejected per `feedback_no_beagle_solutions` (−25 to −30pp concordance on small/medium SVs).

### Why only 2 exclusions, not the 7 originally planned

The original 7-exclusion plan was based on a-priori coverage flags. Empirical concordance shows:

1. **Low ONT coverage (9-15×) does NOT predict actual assembly errors** in 4 of 5 cases. Modern long-read assemblers + cactus pangenome integration handle low ONT coverage well enough that 9-15× assemblies produce variant calls matching short-read PanGenie within normal panel variation.
2. **Heterozygosity flag also doesn't reliably predict failure** — Pi-0 (4 Mb het) has 7.6% disagreement (upper end of normal but not catastrophic).
3. **The catastrophic cases need independent evidence beyond "PG disagrees with cactus".** PG-cactus disagreement could be either side's fault. We swap when independent evidence points to the cactus side:
   - 5772: cactus k-mer J=0.964 to T980 (mislabel proven independently of PG concordance).
   - 9947: Fernando's coverage flag (a-priori warning) confirmed by catastrophic post-hoc concordance.

## Decision 3 — PG-substitute the 7 exclusions (not drop)

**Why substitute, not drop.** All 7 Accession_IDs have 1001G short reads in `loo_ena_manifest.tsv` (PRJNA273563). Keeping the founder via PG preserves the 231-founder panel — important because downstream GrENE-Net GEA expects this footprint.

**ONT 10× vs short-read 10× — which failure mode is worse?**

| Failure mode | Cactus 10× ONT | PG 10× SE |
|---|---|---|
| Error injection | Systematic homopolymer indels baked into FASTA → appear as true founder variants in cactus VCF | Low GQ → GTs set to "." by GQ≥20 filter → missing → treated as REF in cn_var |
| Direction of bias | **Over-call** (false ALTs) | **Under-call** (missing genotypes) |
| Downstream recoverability | None (cn_var has no way to QC) | Yes (GQ filter is tunable; missing → REF is conservative) |
| QC visibility | Invisible | Visible via LOO concordance |

**PG path is the lesser of two evils.** PanGenie is k-mer-based (not alignment-based), genotypes existing pangenome bubbles (can't inject novel variants), and the SE vs PE penalty is smaller than for alignment-based callers.

6. Apply PG-side MAC<2 filter to `pangenie_153_qc.vcf.gz` → `pangenie_153_qc_mac2.vcf.gz`. Then merge cactus_78 + pangenie_153_qc_mac2 → `founders_231_v3qc_raw.vcf.gz`. Recompute AC/AN with `bcftools +fill-tags`. Drop `AC=0` from merged panel → `founders_231_v3qc.vcf.gz`.

    **REVISED 2026-05-16** (twice). Final decision on MAC filtering:

    **PG side (153 diploid founders)**: APPLY `MAC<2`. In diploid context, AC=1 implies exactly one het call (`0/1`). In inbred selfing Arabidopsis, single hets are typically short-read calling artifacts → xwu's MAC≥2 intent applies. Filter: `bcftools view -e 'INFO/AC<2 || (INFO/AN-INFO/AC)<2'` on the standalone PG VCF (so AC reflects PG-only counts).

    **Cactus side (78 haploid founders)**: DO NOT APPLY MAC filter. Haploid AC=1 means one founder genuinely carries the ALT — these are real ecotype-private long-read variants, not artifacts. Keep them.

    **Merged panel**: drop `AC=0` only (catches mono-REF "ghosts" from removing 5772+9947). Records dropped from PG by MAC<2 but present in cactus come back via the merge with PG samples as `./.` (treated as 0 in cn_var, semantically identical to "REF").

    Singleton k-mer filtering for the EM (the "filt2" idea from prior memory) still belongs at the k-mer level in cn_full via `per_sample_per_chrom.py --filt2`, NOT at the variant level here.
7. Rebuild cn_full_231_v3qc: PanGenie-index built **fresh** on merged VCF → `build_kmer_cn.py` (5-chrom array). The fresh index inherits only what survived our filter chain, so cn_full is clean.
8. Rebuild cn_var_231_v3qc (fresh build from merged VCF).
9. Rebuild `unimputed_fastas_v3qc/` for all surviving founders (preserves v3 invariant: same VCF feeds cn_full + cn_var + FASTAs).
